## 完整 STAR 版（面试照这个讲，30 秒讲完）

**S 情境**
在校期间为补齐工程实践能力，独立发起一个自动化测试项目，目标是摆脱“用例散落在脚本里、每加一条用例就要复制粘贴一整段代码”的写法，搭一套能持续维护的框架。

**T 任务**
实现三件事：用例数据与代码解耦、请求层统一封装（含超时与异常处理）、并配套输出一套规范的用例设计文档。

**A 行动**
1. 抽象出 HttpClient 请求层，统一 base_url、超时时间与鉴权头注入入口；对 Timeout / ConnectionError 做捕获并转换为自定义 `APIRequestError`，把原始的网络层报错转成可直接定位的提示信息
2. 将 15 条接口用例抽到 YAML 中，用 `pytest.mark.parametrize` 动态生成，覆盖 GET/POST/PUT/DELETE 四类方法、404 异常场景与 query 参数组合
3. 用 session 级 fixture 管理客户端实例，全会话复用连接，`yield` 模式保证执行结束后自动关闭
4. 独立编写登录模块 17 条用例文档，使用等价类划分与边界值五点法设计，并包含 SQL 注入、账号锁定、空值等反向场景

**R 结果**
- 形成 35 条用例的回归套件，一条命令触发全量执行，耗时约 9 秒
- 新增接口用例从“修改 Python 代码”简化为“YAML 加一行”，零代码改动
- 项目保持连续 7 天每日提交，全部代码开源在 GitHub

## 面试时怎么讲（口语版，别背 bullet）

> “我的项目是一个用 Python + pytest 搭的接口自动化框架。最初的问题是用例和代码混在一起，加一条用例要复制粘贴一整段，所以我做了两件事：一是把请求层封装成 HttpClient，统一超时和异常处理，网络报错会转成能直接定位的自定义异常；二是把用例数据抽到 YAML 里，用 parametrize 动态生成，现在加一条接口用例只需要在 YAML 里加一行，Python 代码一行都不用动。目前是 35 条用例，全量跑约 9 秒。另外我单独写了登录模块 17 条用例文档，用等价类和边界值五点法，包含 SQL 注入、账号锁定这些反向场景。”

**大概率被追问的两个问题（提前准备好）：**

1. “**为什么要做数据驱动？**”
   → 三个点：非技术同学也能维护用例；加用例不碰代码，不会引入语法错误；数据与断言逻辑解耦，改数据不影响框架。

2. “**pytest.raises 是什么场景用的？**”
   → 验证“应该报错”的用例，比如除数为 0、接口传非法参数。反向用例和正向同等重要。

###### TCP三次握手

初始状态

客户端：CLOSE

服务端：先调用 listen()，进入 LISTEN（监听端口，等待连接）

第一次握手（客户端 → 服务端）

客户端发送 SYN 报文

SYN=1，Seq = client\_isn

客户端状态变为：SYN\_SENT

含义：客户端请求建立连接，告知服务端我的初始序号是 client\_isn

服务端收到这个 SYN 包。

第二次握手（服务端 → 客户端）

服务端回复 SYN+ACK 报文

SYN=1，Seq = server\_isn（服务端自己的初始序号）

ACK=1，Ack = client\_isn + 1（确认收到客户端的 SYN）

服务端状态变为：SYN\_RCVD

含义：服务端同意连接；确认收到客户端的报文，同时告诉客户端自己的初始序号。

客户端收到 SYN+ACK 包，客户端状态变成 ESTABLISHED（已建立）。

第三次握手（客户端 → 服务端）

客户端发送 ACK 报文

ACK=1，Ack = server\_isn +1

含义：客户端确认收到服务端的 SYN 报文。

服务端收到这个 ACK 报文后，状态变为 ESTABLISHED。





###### TCP 四次挥手（断开连接）

初始状态

客户端、服务端都处于 ESTABLISHED（连接已建立）

第一次挥手：客户端 → 服务端，发 FIN

客户端没有数据要发送了，发送 FIN 报文，

客户端状态变为：FIN\_WAIT\_1

含义：客户端告诉服务端：我不再发数据给你了，但还可以接收服务端发来的数据。

第二次挥手：服务端 → 客户端，回 ACK

服务端收到 FIN，回复 ACK 确认。

服务端状态变为：CLOSE\_WAIT

客户端收到 ACK 后，状态变为：FIN\_WAIT\_2

含义：服务端确认收到客户端的关闭请求；此时客户端→服务端方向的通道关闭。

⚠️ 服务端还可以继续给客户端发剩余数据。

第三次挥手：服务端 → 客户端，发 FIN

当服务端也没有数据要发送了，发送 FIN 报文。

服务端状态变为：LAST\_ACK

含义：服务端告诉客户端，我这边也没有数据要发，可以关闭了。

第四次挥手：客户端 → 服务端，回 ACK

客户端收到 FIN，回复ACK确认。

客户端进入 TIME\_WAIT，等待 2MSL 之后，客户端最终变为 CLOSE。

服务端收到这个 ACK 后，立刻变成 CLOSE。



###### TCP 和 UDP 区别:

连接

TCP 是面向连接的传输层协议，传输数据前先要建立连接。

UDP 是不需要连接，即刻传输数据。

服务对象

TCP 是一对一的两点服务，即一条连接只有两个端点。

UDP 支持一对一、一对多、多对多的交互通信

可靠性

TCP 是可靠交付数据的，数据可以无差错、不丢失、不重复、按序到达。

UDP 是不可靠的传输协议，不保证可靠交付数据，数据发送之后，丢失了就丢失了。

拥塞控制、流量控制

TCP 有拥塞控制和流量控制机制，保证数据传输的安全性。

UDP 则没有，即使网络非常拥堵了，也不会影响 UDP 的发送速率。

首部开销

TCP 首部长度较长，会有一定的开销，首部在没有使用「选项」字段时是 20 个字节，如果使用了「选项」字段则会变长的。

UDP 首部只有 8 个字节，并且是固定不变的，开销较小。

传输方式

TCP 是流式传输，没有边界，但保证顺序和可靠。

UDP 是一个包一个包的发送，是有边界的，但可能会丢包和乱序。

分片不同

TCP 的数据大小如果大于 MSS 大小，则会在传输层进行分片，目标主机收到后，也同样在传输层组装 TCP 数据包，如果中途丢失了一个分片，只需要传输丢失的这个分片。

UDP 的数据大小如果大于 MTU 大小，则会在 IP 层进行分片，目标主机收到后，在 IP 层组装完数据，接着再传给传输层。



###### HTTP 与 HTTPS 有哪些区别？

HTTP 是超文本传输协议，信息是明文传输，存在安全风险的问题。HTTPS 则解决 HTTP 不安全的缺陷，在 TCP 和 HTTP 网络层之间加入了 SSL/TLS 安全协议，使得报文能够加密传输。

HTTP 连接建立相对简单，TCP 三次握手之后便可进行 HTTP 的报文传输。而 HTTPS 在 TCP 三次握手之后，还需进行 SSL/TLS 的握手过程，才可进入加密报文传输。

两者的默认端口不一样，HTTP 默认端口号是 80，HTTPS 默认端口号是 443。

HTTPS 协议需要向 CA（证书权威机构）申请数字证书，来保证服务器的身份是可信的。





###### 键入网址到网页显示

整体分为六大步骤：DNS 域名解析 → TCP 连接（HTTPS 额外 TLS 握手）→ 发送 HTTP 请求 → 服务器处理并返回响应 → 浏览器解析渲染页面 → TCP 断开连接



线程是进程当中的一条执行流程

线程与进程的比较如下：

进程是资源（包括内存、打开的文件等）分配的单位，线程是 CPU 调度的单位；

进程拥有一个完整的资源平台，而线程只独享必不可少的资源，如寄存器和栈；

线程同样具有就绪、阻塞、执行三种基本状态，同样具有状态之间的转换关系；

线程能减少并发执行的时间和空间开销；

✅面试精简背诵版

进程是操作系统资源分配的基本单位，线程是CPU 调度的基本单位。

进程拥有独立完整资源；同一个进程内的线程共享进程资源，线程仅有私有栈、寄存器。

线程也具备就绪、阻塞、运行三种状态。

创建、切换线程开销远小于进程，并发成本更低。





进程间通信 IPC 方式：管道、命名管道、消息队列、共享内存、信号量、信号、socket 套接字。

管道：半双工，仅限亲缘进程；命名管道支持无亲缘进程。

消息队列：内核消息链表，按类型收发。

共享内存：速度最快，无拷贝，需要额外同步手段。

信号量：用于进程同步互斥，不传递数据。

信号：异步短消息通知。

Socket：支持本地和跨网络主机通信。



死锁四个必要条件：互斥条件，持有并等待条件，不可剥夺条件和环路等待条件



虚拟内存是 OS 内存管理机制，给每个进程独立虚拟地址空间。通过 MMU 硬件和页表完成虚拟地址到物理地址映射，暂时不用的数据放到磁盘交换分区。

特点：多次性、对换性、虚拟性。

作用：扩充内存、进程内存隔离、简化程序地址管理。



## 测试左移

**定义**：测试左移就是把测试活动向软件研发周期的 ** 左侧（前期）** 提前介入，在需求评审阶段就参与进来，而不是等开发写完代码才开始测试。

**核心目的**：尽早发现需求漏洞、逻辑缺陷、歧义点，从源头降低缺陷产生的概率，越早发现 bug，修复成本越低。

**落地动作**：参与需求评审、需求测试、编写测试用例、静态代码评审，在编码前就识别风险。

## 测试右移

**定义**：测试右移是把测试活动向研发周期 ** 右侧（上线后）** 延伸，重点做线上监控、灰度发布、线上用户行为观测。

**核心目的**：获取真实生产环境的数据，发现预发环境无法复现的线上问题，评估新版本在真实用户场景下的表现。

**落地动作**：灰度放量、线上日志监控、用户反馈收集、线上拨测、生产环境巡检。

## 持续测试

**定义**：持续测试是 CI/CD 体系下的测试实践，随着代码每一次提交，自动执行分层测试（单元、接口、UI 自动化），持续反馈质量结果。

**核心目的**：保障每次代码变更都能快速得到质量反馈，支撑持续集成、持续交付，让软件可以安全、频繁地发布。

**落地动作**：自动化测试脚本接入流水线，代码提交自动触发测试，快速给出质量报告。

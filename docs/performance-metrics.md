# 性能测试指标速查（Day 18）

> 面试被问"做过性能测试吗"时，能把这几个词讲清楚 + 说出自己跑过一次，就够用了。
> **不要深挖**——性能测试是社招才深聊的方向，校招阶段知道指标含义 + 亲手跑过一次 Locust 即可。

---

## 一、核心指标

| 指标 | 含义 | 怎么读 |
|---|---|---|
| **TPS** | Transactions Per Second，每秒完成的事务数 | 系统处理能力的主指标。越高说明吞吐越强 |
| **QPS** | Queries Per Second，每秒查询数 | 与 TPS 常混用；严格说 QPS 针对查询，TPS 针对事务 |
| **响应时间** | 一次请求从发出到收到响应的耗时 | 常看**平均值 / 中位数 / P95 / P99**，不能只看平均值 |
| **并发数** | 同时向系统发请求的用户数 | 注意「并发用户」≠「在线用户」，在线用户大部分时间在思考 |
| **错误率** | 失败请求数 / 总请求数 | **超过 1% 就要警惕**；压测中错误率陡升通常意味着系统到瓶颈了 |
| **吞吐量** | 单位时间处理的数据量（可指字节数） | 与 TPS 区分：TPS 数请求，吞吐量可指数据体积 |

## 二、为什么必须看 P95 / P99，而不是只看平均值

假设 100 个请求里 95 个耗时 50ms，5 个耗时 5s：

- 平均值 ≈ 297ms —— **看起来还行**
- P95 = 50ms，但 **P99 ≈ 5s** —— 真实情况是每 100 个用户有 1 个卡 5 秒

**平均值会把慢请求淹没掉。** 线上事故往往是那 1% 的慢请求引发的连锁反应，所以 SLA 通常按 P95 / P99 约定。

## 三、Locust 里在哪看

| 位置 | 内容 |
|---|---|
| **Charts 标签页** | Total Requests per Second（**TPS 曲线**）、Response Times（**响应时间曲线**，含中位/P95）、Number of Users（并发曲线） |
| **Statistics 标签页** | 请求数、失败数、失败率、平均 / 中位 / P95 / P99 / 最大 响应时间、当前 RPS |
| **Failures 标签页** | 失败详情与错误信息 |
| 终端 summary | `--headless` 模式跑完后的汇总表 |

## 四、本次实测结果（本地 mock 服务）

配置：5 个并发用户，每秒增加 1 个，持续 10 秒。

| 指标 | 数值 |
|---|---|
| RPS | 约 18 |
| 失败率 | 0 |
| 被测对象 | Flask 自带开发服务器（`app.run`） |

**如何解读这 18 RPS：**
这个数字反映的是**Flask 开发服务器**的处理上限，不是业务逻辑慢。Flask 的 `app.run()` 是单进程开发服务器，**明确禁止用于生产**（启动时 werkzeug 自己会打印警告）。生产环境要换成 gunicorn / uWSGI 多进程部署，RPS 会高一个量级。

**这就是压测解读的第一原则：测出数字之前，先确认被测环境的规格。** 否则你会把"开发服务器性能差"误判成"接口有性能问题"。

## 五、压测的两条纪律

1. **只压自己的服务。** 对第三方公共服务（比如 jsonplaceholder）压测 = 发起 DoS 攻击，违反服务条款，可能违法。
2. **不要压生产环境。** 压测要压测试环境；确需压生产必须提前报备、低峰期、控制并发。

## 六、Locust 的一个经典坑（本次踩到）

**Locust 默认把 HTTP 4xx / 5xx 都记为「失败」。**

但如果压测场景里本来就包含「期望返回 400」的非法入参用例，这些 400 会被算成失败，导致**失败率虚高**，看起来像服务有问题。

正确做法是用 `catch_response=True` 手动标记：

```python
with self.client.post("/users", json={"id": -1}, catch_response=True) as resp:
    if resp.status_code == 400:
        resp.success()                      # 400 是预期结果，算成功
    else:
        resp.failure(f"期望 400，实际 {resp.status_code}")
```

**面试价值**：这说明你理解「业务预期」和「HTTP 语义」是两回事——压测统计口径要对齐业务语义，而不是照搬状态码。
